# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа `Linear(4, 8) → ReLU → Linear(8, 3)` на датасеті **Iris**. Прямий прохід,
чисельно стабільна крос-ентропія та зворотний прохід реалізовані **вручну в NumPy**
(усі обчислення у `float64`, автоматичне диференціювання не використовується).
Коректність ручних градієнтів перевірена **двома незалежними способами**:
звіркою з PyTorch autograd та чисельним диференціюванням (метод центральної різниці).
Окремо проведено контрольований дослід із навмисно внесеною помилкою, щоб
показати, що обидва методи перевірки цю помилку виявляють.

## 4. Архітектура та ініціалізація

```
X → Linear(4, 8) → ReLU → Linear(8, 3) → логіти 3 класів
```

Функція втрат — крос-ентропія, усереднена за обʼєктами в батчі.

| Параметр | Розмірність | Ініціалізація |
|---|---|---|
| `W1` | 4 × 8 | He: `N(0, √(2/4))`, fan_in = 4 |
| `b1` | 8 | нулі |
| `W2` | 8 × 3 | Xavier: `N(0, √(2/(8+3)))`, fan_in + fan_out = 11 |
| `b2` | 3 | нулі |

Один спільний `rng = np.random.default_rng(0)`; генерація виконується **по
черзі**: спочатку `W1`, потім `W2` (зсуви — нулі, тому rng на них не
витрачається). Архітектура та порядок ініціалізації в коді не змінюються
відносно умови завдання.

## 5. Формули прямого проходу

```
z1     = X @ W1 + b1              # (N, 8)
a1     = ReLU(z1)                 # (N, 8)
logits = a1 @ W2 + b2             # (N, 3)
```

Чисельно стабільний **log-softmax** зі зсувом на максимум (щоб уникнути
переповнення `exp` для великих логітів):

```
shifted = logits - max(logits, axis=1, keepdims=True)
log_p   = shifted - log(sum(exp(shifted), axis=1, keepdims=True))
p       = exp(log_p)
```

Крос-ентропія, усереднена за N обʼєктами батча:

```
L = -(1 / N) * Σ_i log_p[i, y_i]
```

---

## 6. Формули зворотного проходу

Похідні виводяться за допомогою правила ланцюжка, рухаючись від функції
втрат до вхідних параметрів `W1, b1, W2, b2`:

```
dlogits = (p - onehot(y)) / N        # (N, 3)  ← градієнт крос-ентропії + softmax
dW2     = a1.T @ dlogits             # (8, 3)
db2     = Σ_i dlogits[i]             # (3,)
da1     = dlogits @ W2.T             # (N, 8)
dz1     = da1 * 1[z1 > 0]            # (N, 8)  ← похідна ReLU (0 при z1 ≤ 0, 1 при z1 > 0)
dW1     = X.T @ dz1                  # (4, 8)
db1     = Σ_i dz1[i]                 # (8,)
```

### Проміжні значення, що зберігаються після прямого проходу

Ці значення обчислюються в `forward()` і кешуються, бо без них зворотний
прохід неможливо порахувати:

| Значення | Розмірність | Навіщо потрібне у `backward()` |
|---|---|---|
| `X` | (N, 4) | множник у `dW1 = X.T @ dz1` |
| `z1` | (N, 8) | знак `z1` задає маску похідної ReLU (`z1 > 0`) |
| `a1` | (N, 8) | множник у `dW2 = a1.T @ dlogits` |
| `p` | (N, 3) | softmax-імовірності, потрібні для `dlogits = (p - onehot(y)) / N` |
| `y` | (N,) | цільові класи, потрібні для побудови `onehot(y)` |

### Розмірності вихідних градієнтів

| Градієнт | Розмірність | Відповідає параметру |
|---|---|---|
| `dW1` | 4 × 8 | `W1` |
| `db1` | 8 | `b1` |
| `dW2` | 8 × 3 | `W2` |
| `db2` | 3 | `b2` |

## 8. Звірка NumPy vs PyTorch

Створено еквівалентну мережу `TorchNet` у PyTorch і скопійовано в неї ті самі
параметри. Важлива деталь: `torch.nn.Linear` зберігає вагу як `(out_features,
in_features)`, тобто **транспоновано** відносно масивів NumPy:

```
linear1.weight = W1.T   # (4, 8) → (8, 4)
linear2.weight = W2.T   # (8, 3) → (3, 8)
```

Градієнти, отримані з `.grad` у PyTorch, транспонуються назад у формат
NumPy-масивів перед порівнянням. Втрата рахується через
`F.cross_entropy(logits, y)`, яка за замовчуванням усереднює за обʼєктами —
так само, як і ручна реалізація.

**Критерій:** `|a − b| ≤ 1e-12` для кожної пари скалярних значень, усі
значення мають бути скінченними.

| Величина | Макс. абс. різниця (NumPy vs PyTorch) | Перевірку пройдено |
|---|---|---|
| Loss | 2.220e-16 | Так |
| Градієнт `W1` | 2.776e-17 | Так |
| Градієнт `b1` | 3.643e-17 | Так |
| Градієнт `W2` | 1.110e-16 | Так |
| Градієнт `b2` | 1.388e-16 | Так |

Значення втрат окремо:

```
Loss NumPy   = 1.456200780114282
Loss PyTorch = 1.456200780114282
```

Усі різниці лежать на рівні машинної похибки округлення `float64`
(`1e-16 … 1e-17`), що на кілька порядків менше за поріг `1e-12` —
усі пʼять перевірок пройдено.

## 9. Чисельна перевірка окремих градієнтів

Формула чисельної похідної (метод центральної різниці), `ε = 1e-6`:

```
g_num = (L(θ + ε) − L(θ − ε)) / (2ε)
```

Порівнюється з відповідним елементом градієнта, який повертає `backward()`
на тих самих початкових вагах і тій самій вибірці (N = 105).

**Критерій:** `|g_num − g_manual| ≤ 1e-7`.

| Параметр | Градієнт `backward()` | Чисельна похідна | Абс. різниця | Перевірку пройдено |
|---|---|---|---|---|
| `W1[0,0]` | −0.019920184 | −0.019920184 | 6.03e-11 | Так |
| `b1[0]` | −0.070566112 | −0.070566112 | 3.63e-11 | Так |
| `W2[0,0]` | 0.135230209 | 0.135230209 | 9.22e-11 | Так |
| `b2[0]` | 0.085521645 | 0.085521645 | 1.46e-10 | Так |

Усі чотири перевірки пройдено — ручна реалізація `backward()` узгоджена з
незалежним чисельним диференціюванням, різниці на 3–4 порядки менші за поріг.

## 10. Дослід із навмисною помилкою

**Внесена помилка:** у формулі `dlogits` прибрано ділення на кількість
обʼєктів `N`. Функція втрат при цьому лишається незмінною — так само
усередненою за обʼєктами. Помилка ізольована в `backward(bug_mode=True)`
і вмикається лише явно; за замовчуванням працює коректна реалізація.

### Прогноз (записаний до запуску)

- Втрата на початкових параметрах **не зміниться** — `forward()`/loss не
  залежать від `bug_mode`, помилка стосується лише формули градієнта за
  логітами, а не самої функції втрат.
- Усі чотири ненульові градієнти (`dW1, db1, dW2, db2`) зростуть за модулем
  **рівно у N = 105 разів**, оскільки лінійно залежать від `dlogits`, а
  `dlogits_bug = N · dlogits_correct`.
- Звірка з PyTorch (де `cross_entropy` коректно ділить на `N` через
  усереднення) виявить розбіжність ≈105× для всіх чотирьох градієнтів;
  значення втрат при цьому співпадуть.
- Чисельна перевірка також провалиться для всіх чотирьох параметрів, бо
  чисельна похідна спирається на незмінену loss, а `backward()` поверне
  значення в N разів більше за поріг `1e-7`.

### Фактичний результат

```
loss (коректна)   = 1.456200780114282
loss (з помилкою) = 1.456200780114282     |diff| = 0.0e+00   → прогноз підтверджено

||grad_bug|| / ||grad_correct||:
  W1: 105.000000   b1: 105.000000   W2: 105.000000   b2: 105.000000
  (очікувано N = 105) → прогноз підтверджено
```

**Звірка з PyTorch (`bug_mode=True`):**

```
loss NumPy(bug) = 1.456200780114, loss PyTorch = 1.456200780114, |diff| = 2.220e-16
```

| Градієнт | Макс. абс. різниця (NumPy_bug vs Torch) | Перевірку пройдено |
|---|---|---|
| `W1` | 1.852e+01 | Ні |
| `b1` | 1.564e+01 | Ні |
| `W2` | 3.419e+01 | Ні |
| `b2` | 1.120e+01 | Ні |

Loss співпадає (не залежить від помилки), а всі чотири градієнти сильно
розходяться з PyTorch-еталоном — помилку виявлено.

**Чисельна перевірка (`bug_mode=True`):**

| Параметр | Градієнт `backward()` (bug) | Чисельна похідна | Абс. різниця | Перевірку пройдено |
|---|---|---|---|---|
| `W1[0,0]` | −2.091619355 | −0.019920184 | 2.07e+00 | Ні |
| `b1[0]` | −7.409441716 | −0.070566112 | 7.34e+00 | Ні |
| `W2[0,0]` | 14.199171904 | 0.135230209 | 1.41e+01 | Ні |
| `b2[0]` | 8.979772708 | 0.085521645 | 8.89e+00 | Ні |

Усі чотири перевірки не пройдено (очікувано) — обидва незалежні способи
звірки (PyTorch і чисельне диференціювання) виявили помилку.

### Висновок

Фактичний результат повністю збігається з прогнозом: втрата не змінилась,
усі градієнти зросли рівно в N = 105 разів, і обидва незалежні способи
звірки (PyTorch autograd і чисельне диференціювання) виявили помилку.
Після досліду коректну реалізацію відновлено — це реалізація за
замовчуванням (`bug_mode=False`), окремий скрипт `bug_experiment.py`
дозволяє відтворити помилковий режим ізольовано, не зачіпаючи основний
пайплайн у `main.py`.
